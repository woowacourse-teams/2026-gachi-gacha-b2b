# 점주용 매장·가챠 재고·쿠지 현황판 로드맵

2026-11-03 기준 프론트엔드 계약과 유사 제품 공식 문서를 바탕으로 정리했다. 이 문서는 구현 순서와 데이터 경계를 기록한다. 백엔드·안드로이드 코드는 변경하지 않는다.

`createdAt`은 서비스 카탈로그 등록일이다. 출시일이나 점포 입고일로 표시하지 않는다. 기존 매장 연결 수는 수량이 아니라 등록된 가챠 _종류_ 수다.

선택형 보강은 BFF 런타임의 `B2B_CATALOG_CSV_URL`에 공개 Google Sheet의 CSV 게시 주소를 넣었을 때만 켜진다. 현재 실제 시트는 설정되지 않았다. 필수 헤더는 `gacha_id,name_ko,name_ja,aliases,work,series,characters,reviewed_at`이다. 기존 가챠 ID를 키로 합치며 별칭·캐릭터 여러 값은 `|`로 구분한다. 중복 ID·잘못된 행은 제외하고, 미설정이나 CSV 장애 시 기존 카탈로그 검색을 유지한다. CSV는 읽기 전용이고 점포 수량을 저장하지 않는다. [README의 설정과 상태 설명](../README.md#선택형-google-sheet-카탈로그-보강)에 운영 절차를 적었다.

## 목표 화면 흐름

1. 점주가 권한 있는 매장을 고른다. 등록된 가챠 종류, 품절, 보충 필요 건수를 요약한다.
2. 공용 카탈로그에서 한글·일본어 이름, 별칭, 작품·시리즈·캐릭터, 카테고리로 찾는다. 결과에 썸네일과 출처를 보여준다.
3. 가챠를 선택하고 최초 수량만 입력해 등록한다. 가격, 기계/슬롯, 목표 수량은 선택 입력으로 둔다. 같은 상품을 여러 슬롯에 놓을 수 있는지 데이터 모델에서 결정한다.
4. 매장 목록에서는 검색·필터·정렬, 빠른 증감, 실사, 품절/판매중지, 보충 목록, 변경 이력을 제공한다. 삭제는 실수 방지를 위해 비활성화와 구분한다.
5. 쿠지는 별도 `현황판` 탭에서 타이틀과 실제 상자/로트를 선택해 등급별 잔여 장수와 총 잔여 장수를 관리한다. 마지막 갱신 시각과 수기 입력 상태를 보여준다.
6. 기간별 대시보드는 *확인된 판매 이벤트*와 수기 조정/파손/이동을 분리한다. 소비자 검색·상세 조회·찜은 별도의 관심 지표로 표시한다.

### 쿠지는 가챠 수량과 별도로 다룬다

[BANDAI SPIRITS의 공식 구매 안내](https://sf.1kuji.com/1kuji_japan/)에 따르면 쿠지는 한 장을 뽑아 해당 등급 경품을 받고, 마지막 장을 뽑은 경우 라스트원 경품을 **추가로** 받는다. [공식 온라인 안내](https://on-line.1kuji.com/Page/guide.aspx)도 상품 다음에 상자를 고르고 남은 등급을 확인하는 흐름이며 라스트원이 없는 상품도 있다. 따라서 같은 타이틀의 상자 여러 개를 하나의 재고로 합치지 않고, 일반 등급 잔여 합계를 총 잔여 장수로 계산하며 라스트원은 그 합계에 넣지 않는다. 더블찬스도 점포 경품 재고와 분리한다.

점주 조작은 `추첨 결과 등급 선택 → 해당 등급 −1 → 총 잔여 자동 갱신`으로 단순화한다. 실사 정정에는 사유를 남긴다. 등급 안에 여러 디자인이 있어도 디자인별 실제 수량을 확인할 수 없다면 디자인별 재고로 표시하지 않는다. 소비자에게 공개할 경우 [공식 점포 재고 페이지](https://bandainamco-am.co.jp/chara_shop/ichibankuji-official-shop/NEWS/hikone/stock/)처럼 판매 상태와 마지막 갱신 시각을 함께 표기하고, 점주 수기 갱신을 자동 실시간 재고처럼 표현하지 않는다.

현재 매장 생성 API의 `kujiAmount`와 가격 범위는 타이틀/상자/등급의 조회·수정 API가 아니다. API에 저장 가능한 것은 매장 수준 정보까지다. 현황판을 여러 기기에서 공유하거나 소비자 화면에 노출하려면 최소한 점주 권한이 적용된 `CatalogKuji`, `KujiBox`, `KujiEvent` 읽기·쓰기 계약이 필요하다. 소규모 파일럿은 인증된 Apps Script/Sheet 저장소를 검토할 수 있지만, 공개 CSV만으로 잔여 장수를 수정하지 않는다. 공식 이미지·문구·데이터의 S3 재호스팅은 사용 권리 확인 후 진행한다.

현장 검증용 `쿠지 기록 양식 CSV`는 선택 매장의 ID·이름을 채우고 타이틀·수량은 비워 둔다. 한 행에 한 상자의 한 등급을 기록하며, 1회 가격·초기/현재 장수·라스트원 유무/지급·최종 실사일·메모를 적을 수 있다. 다운로드 파일은 점주의 기기에만 남고 서비스에 저장·동기화되지 않는다. 소비자 화면의 재고나 완판 상태에도 반영되지 않으며, 이 기능을 실시간 현황판으로 소개하지 않는다.

## 구현 순서와 완료 기준

### 0. 지금 반영할 프론트 정리

- 자동 이미지 분류 추천, AI 설정·키 입력·추천 서버 라우트·목 응답·관련 테스트를 제거한다. 수동 이름/카테고리 분류와 통합 검색 BFF는 유지한다.
- 매장 등록 가챠의 이름·카테고리·출처·카탈로그 등록일을 검색 필터와 독립적으로 표시한다. 등록 수는 종류 수라고 명시한다.
- 완료 기준: AI 추천 요청 경로가 사라지고 수동 분류·매장 검색·연결·검색 BFF가 통과한다.

### 1. 현재 API만으로 운영 편의 개선

- 검색 결과의 한국어 기본 이름·썸네일·카테고리·출처·등록일을 읽기 쉽게 배치한다. 선택→매장 연결은 기존 `POST /stores/{storeId}/gachas/{gachaId}`를 사용한다.
- 매장 등록 목록에 검색·카테고리 필터·정렬·CSV 내보내기를 붙인다. CSV는 **상품 종류 목록**이며 재고 수량 파일로 오인되지 않게 한다.
- 쿠지 상자·등급 운영 방식을 확인할 빈 현장 기록 CSV 양식을 내려받게 한다. 파일은 사이트에 다시 올라오거나 영속 저장되지 않는다.
- 중복 선택, 응답 지연, 삭제 확인, 빈 결과, 이미지 오류, 모바일 폭을 검증한다.
- 완료 기준: 기존 API만으로 검색→연결→등록 목록 확인·해제와 CSV 내보내기가 가능하다.

### 2. 한·일 이름과 상세 분류 보강

- `gachaId`를 키로 한 한국어/일본어 이름, 별칭, 작품·시리즈·캐릭터를 선택형 공개 Google Sheet CSV에서 읽는 BFF 경로를 마련했다. `B2B_CATALOG_CSV_URL`은 아직 비어 있으며 실제 데이터의 출처·검수 책임과 중복/번역 규칙은 정해야 한다.
- 공개 CSV는 읽기 전용 메타데이터에만 사용한다. BFF는 5분 캐시, 마지막 정상본, `disabled`/`fresh`/`stale`/`unavailable` 상태와 마지막 정상 조회 시각을 제공한다. 화면에서는 상태와 갱신 실패를 정확히 표시하고, 이름 보강이 없으면 기존 API 이름을 사용한다.
- 검색 BFF는 기존 카탈로그와 보강 데이터를 `gachaId`로 합친다. 카테고리 필터는 기존 분류에만 적용하며 임의의 텍스트를 작품·캐릭터로 자동 추론하지 않는다. 제조사·출시일 보강은 아직 지원하지 않는다.
- 쿠지 공용 카탈로그는 가챠와 별도 스키마로 시작한다. 우선 점주가 직접 입력한 타이틀·가격·등급별 초기 장수·라스트원 유무를 파일럿에서 검증하고, 공식 메타데이터·이미지 자동 수집은 데이터 사용 권리와 검수 체계를 확보한 뒤 진행한다.
- 완료 기준: 한·일 이름과 별칭 검색이 일관되고, 잘못된 시트 행이 기존 가챠 표시를 망가뜨리지 않는다.

### 3. 가챠 수량·쿠지 현황판 저장소

- 여러 기기에서 공유할 영속 저장소와 점주별 매장 권한을 먼저 마련한다. 프론트 팀 BFF의 별도 저장소가 기본 후보이며, 작은 파일럿은 인증된 Apps Script/Sheet도 가능하다.
- API는 `GET stock`, `POST stock event`, `POST count`, `PATCH paused`, `GET history`처럼 이벤트 기반으로 설계한다. `version` 또는 조건부 갱신과 멱등 키로 동시 수정/재시도를 처리한다. 수량 음수 방지, 서버 시각, 권한 확인, 백업과 복원도 포함한다.
- Google Sheet를 쓰는 경우 공개 CSV 쓰기는 사용하지 않는다. Apps Script 웹 앱의 실행 주체·접근 범위를 제한하고 [LockService](https://developers.google.com/apps-script/reference/lock)로 동시 수정을 직렬화한다. [Sheets API 할당량](https://developers.google.com/workspace/sheets/api/limits)과 장애 시 재시도, 이력 백업을 검증한 파일럿으로 한정한다.
- 같은 저장소/권한 기반에 쿠지 상자와 등급별 잔여, 추첨·실사 이벤트를 추가한다. 총 잔여는 일반 등급 잔여의 합으로 계산하고, 마지막 장의 등급 경품과 라스트원 지급을 하나의 원자적 사건으로 기록한다. 여러 상자와 라스트원 없음도 테스트한다.
- 가챠 완료 기준: 한 점포의 두 기기에서 수량·품절·입출고 이력이 일치하고, 동시 수정·중복 요청으로 수량이 깨지지 않는다.
- 쿠지 완료 기준: 두 기기에서 같은 상자의 등급별 잔여·총 잔여·라스트원 상태가 일치하고, 추첨 재시도로 두 장이 빠지지 않는다.

### 4. 엑셀 대체와 보충 운영

- 기계/슬롯 매핑, 최소·목표 수량, 보충 목록, 실사 차이, CSV 가져오기(열 매핑·미리보기·중복 검증)와 내보내기를 추가한다.
- 점주가 직접 입력한 조정과 자동 판매 이벤트를 구분한다. 오프라인 작업이 필요하면 충돌 해결 규칙과 마지막 동기화 시각을 화면에 명시한다.
- 쿠지 현황판에는 판매 예정/판매 중/완판/일시중지 상태, 상자 교체, 등급별 실사, 라스트원 지급 확인, 상자별 이력·CSV를 제공한다. 소비자 공개는 별도 API 계약과 갱신 지연 표시가 확인된 뒤에만 진행한다.
- 완료 기준: 점주가 기존 엑셀의 일상 업무를 목록·보충·실사·이력에서 처리하고 CSV로 원본을 회수할 수 있다.

### 5. 신뢰 가능한 분석

- 결제/POS 또는 기계 판매 이벤트가 있을 때만 기간별 판매량·매출·판매율·품절 시간을 계산한다. 없으면 입출고 사유를 분리한 `수기 기록 기반 소진 추정`으로 표기한다.
- 관심도는 소비자 검색·조회·찜·재입고 요청의 집계 권한과 이벤트 중복 제거가 확보된 뒤 별도 대시보드로 만든다. 소량 표본에는 최소 표본 수와 기간을 표시한다.
- 완료 기준: 보고서의 각 지표가 원천 이벤트, 기간, 점포, 제외 사유로 재현된다.

## 꼭 필요한 외부 계약

프론트 코드만으로 점주 인증, 매장 소유권, 소비자 앱에 표시할 수량/완판, 결제 이벤트를 만들어낼 수는 없다. 백엔드 팀에는 먼저 **점주↔매장 권한과 기존 매장 가챠 연결의 중복 방지**를 요청하고, 점주용 저장소가 준비된 뒤 **소비자 조회 API의 재고·품절 반영**, 분석 단계에서 **판매·관심 이벤트의 안전한 제공 계약**을 요청한다. 쿠지는 별도로 **타이틀·상자·등급·라스트원과 추첨 이벤트 계약**이 필요하다. 프론트 팀 BFF가 수량을 보관하더라도 소비자 API와 Android 화면에 반영하려면 별도 읽기 계약이 필요하다.

## 미결정 사항

- 한 시리즈를 여러 기계/슬롯에 동시에 넣는지, 기계별 수량까지 관리할지.
- 점주가 판매를 수동 기록할지, 기계/POS에서 이벤트를 받을 수 있는지.
- 점주 로그인·매장 권한의 주체와 현재 프론트 EC2의 지속 저장소·백업 운영 여부.
- 한국어/일본어 이름과 작품·캐릭터 데이터의 제공자, 검수자, 공개 범위.
- 쿠지별 상자 구성과 등급 수량의 입력 주체, 라스트원 지급 확인 방법, 공식 이미지·메타데이터 사용 권리.

이 결정은 수량 저장 및 대시보드 구조를 바꾸므로 3단계 착수 전에 실제 점주 2~3곳의 엑셀 양식과 보충 동선을 확인한다.
